=== Spell Checker

The {productname} {release-version} release includes an accompanying release of the **Spell Checker** premium plugin.

**Spell Checker** includes the following fix.

==== Words inside a `script` element were spellchecked when the `script` was the only content of the editor.
// #TINYMCE-15087

Previously, when a `+<script>+` element was the only content of the editor, the **Spell Checker** plugin sent the words inside the element for spell checking. The plugin skipped `+<script>+` elements elsewhere in the content, but did not skip the element when all of the text to check was inside the element. As a result, the plugin checked script code as if it were editor content.

In {productname} {release-version}, the **Spell Checker** plugin skips the content of a `+<script>+` element, including when the element is the only content of the editor. The plugin checks only the editor content outside the element.

For information on the **Spell Checker** plugin, see: xref:introduction-to-tiny-spellchecker.adoc[Spell Checker].

[[bug-fixes]]
== Bug fixes

{productname} {release-version} also includes the following bug fix<es>:

=== <TINY-vwxyz 1 changelog entry>
// #TINY-vwxyz1

// CCFR here.

=== Node positioned context toolbars repositioned above the editor when the node width was less than the toolbar.
// #TINYMCE-13900

Previously, in inline mode, a context toolbar that used `+position: 'node'+` moved above the editor when the selected node was narrower than the toolbar. For example, when a user resized an image to a width smaller than the context toolbar, the toolbar jumped from the image to a position above the editor. The toolbar then appeared detached from the node it applied to.

In {productname} {release-version}, a context toolbar that uses `+position: 'node'+` stays attached to the selected node, even when the node is narrower than the toolbar. When a user resizes an image to a width narrower than the context toolbar, the toolbar remains above the image.

=== Following an anchor link to a target inside a collapsed `+details+` element, such as a closed accordion, now expands it, as browsers do when navigating to an in-page link
// #TINYMCE-14737

Previously, when a link to an anchor inside a closed accordion was followed, {productname} scrolled to the target but left the accordion closed, so the target content stayed hidden.

In {productname} {release-version}, the editor opens every closed `+<details>+` element that hides the target, including accordions, before scrolling to it. This applies when a link is followed with Ctrl+click (Cmd+click on macOS), with the Alt+Enter keyboard shortcut (⌥+Enter on macOS), with the *Open link* context menu item or toolbar button, or with a click in a disabled editor. For the full list of editor shortcuts, see xref:keyboard-shortcuts.adoc#editor-keyboard-shortcuts[Editor keyboard shortcuts]. In design mode, the accordion stays open in the editor content. In read-only and disabled modes, the accordion opens on screen only, and the editor content does not change.

=== Leaving a list with Enter copied the list item's styles onto the new paragraph.
// #TINYMCE-13035

Previously, when a user pressed Enter on an empty list item to leave a list, {productname} copied the styles of the list item to the new paragraph. For example, when a user applied bold to the entire content of a list item and pressed Enter twice to leave the list, the new paragraph inherited the `+font-weight+` style. Text typed in the paragraph stayed bold after the user turned bold off, and applying bold again added the bold format a second time. Color, font size, and font family set on a list item carried over to the new paragraph in the same way.

In {productname} {release-version}, the editor copies the styles of an empty list item only when the new block is also a list item. A paragraph created by leaving a list no longer inherits the list item styles, so bold, italic, and other formats toggle as expected.

=== The image dialog got stuck on "Uploading image" when an empty or unreadable file was selected on the Upload tab.
// #TINYMCE-7202

Previously, when a user selected an empty file, such as a 0-byte `+.png+` file, on the Upload tab of the image dialog, the dialog stayed on the "Uploading image" message, and the browser console showed an error. The dialog remained blocked and displayed no message about the problem.

In {productname} {release-version}, when the image dialog cannot read the selected file or convert it to image data, the dialog cancels the upload and displays a "Failed to upload image" alert. After the user closes the alert, the dialog accepts input again, and the user can select a different file.

=== Long item text in dialog listboxes overflowed the dialog
// #TINYMCE-14261

Previously, the menu of a listbox in a dialog grew to fit the longest item in the list. When an item had long text, such as an anchor with a long `+id+` in the *Anchors* field of the *Insert/Edit Link* dialog, the open menu extended past the edge of the dialog. The selected value also overflowed the field. The dialog displayed a horizontal scrollbar and the layout broke, which made the dialog difficult to read and use.

In {productname} {release-version}, the menu of a dialog listbox matches the width of the field, and long items wrap onto several lines. When the selected value is too long for the field, the listbox truncates the value with an ellipsis. Long listbox items no longer break the dialog layout or add a horizontal scrollbar.

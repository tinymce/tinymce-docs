=== TinyMCE AI

The {productname} {release-version} release includes an accompanying release of the **TinyMCE AI** premium plugin.

**TinyMCE AI** includes the following fix and addition.

==== Document context was not restored when resuming a conversation in a single editor with the `+tinymceai_document_name+` option set
// #TINYMCE-14994

Previously, when the xref:tinymceai.adoc#tinymceai_document_name[`+tinymceai_document_name+`] option was set on an editor that was not part of a multi-editor group, reopening a conversation that included the document from the xref:tinymceai-chat.adoc#chat-history[chat history] did not restore the document. The **TinyMCE AI** plugin tried to match the saved document name against the editors of a group. Without a group, the plugin found no match, so no context tag for the editor content appeared above the prompt input. The next prompt did not include the document, and the plugin could not apply the changes that the AI suggested in reply.

In {productname} {release-version}, when a user resumes a conversation in an editor that is not part of a group, the plugin restores the context tag for the editor content, whether or not `+tinymceai_document_name+` is set. The next prompt includes the document, and the plugin can apply the changes that the AI suggests. In a xref:tinymceai-multi-editor.adoc[multi-editor group], when none of the saved document names match an editor in the group, the plugin now attaches the content of every editor in the group, as it does for a new conversation, instead of attaching no document.

For information on the **TinyMCE AI** plugin, see: xref:tinymceai-chat.adoc#current-document-and-selection[Current document and selection].

==== New `+TinyMCEAIDiscardSuggestions+` command to discard the AI suggestions previewed in an editor
// #TINYMCE-15157

Previously, integrations had no public way to discard the AI suggestions previewed in an editor. In decoupled mode, the **TinyMCE AI** plugin does not show its own confirmation dialog before the AI view closes, so an integration that detected pending suggestions could not complete its own prompt to discard them.

In {productname} {release-version}, the new `+TinyMCEAIDiscardSuggestions+` command discards the AI suggestions previewed in the editor it runs on, without applying any of them. The editor keeps the content it had before the preview, and returns to the editor mode it had before the preview. In a xref:tinymceai-multi-editor.adoc[multi-editor group], the command affects only the editor it runs on, so an integration runs the command on each editor in the group to discard every suggestion. For details, see xref:tinymceai.adoc#tinymceai-discard-suggestions[Discarding previewed suggestions].

For information on the **TinyMCE AI** plugin, see: xref:tinymceai.adoc[TinyMCE AI].

=== The `+table_appearance_options+` option now also accepts an object with `+cellspacing+`, `+cellpadding+`, `+borderwidth+` and `+caption+` keys, to hide individual fields in the Table Properties dialog
// #TINYMCE-11998

Previously, the xref:table.adoc#table_appearance_options[`+table_appearance_options+`] option showed or hid the **Cell spacing**, **Cell padding**, **Border width**, and **Caption** fields of the Table Properties dialog only as a group. Integrators who wanted to stop authors from changing one field, such as **Cell spacing**, also had to hide the other three fields.

In {productname} {release-version}, the option also accepts an object that controls each field separately. A field set to `+false+` is hidden, and a field set to `+true+` or left out stays visible. For example, `+table_appearance_options: { cellspacing: false }+` hides only the **Cell spacing** field. The `+true+` and `+false+` values work as before.

=== Saving the Table Properties dialog with `+table_appearance_options+` hiding fields no longer removes the table's existing cell spacing, border width or caption
// #TINYMCE-15197

Previously, when the xref:table.adoc#table_appearance_options[`+table_appearance_options+`] option hid fields in the Table Properties dialog, saving the dialog cleared the existing values of the hidden fields on the table. For example, with **Cell spacing**, **Border width**, and **Caption** hidden, changing only the **Width** of a table and clicking **Save** removed the cell spacing of the table and its border width, reset a `+border+` attribute such as `+border="3"+` to `+1+`, and deleted the table caption. The dialog did not show the hidden fields, so users could not see the change or restore the lost values from the dialog.

In {productname} {release-version}, saving the Table Properties dialog leaves the values of hidden fields unchanged on the table. {productname} also no longer applies the xref:table-options.adoc#table_default_styles[`+table_default_styles+`] and xref:table-options.adoc#table_default_attributes[`+table_default_attributes+`] values for a hidden field over the existing value. Saving the dialog changes only the fields that the dialog shows, and the cell spacing, border width, cell padding, and caption of the table stay as they were.

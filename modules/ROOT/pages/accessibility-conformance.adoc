[[conformance-targets]]
== Conformance targets

{productname} is developed and tested against the following accessibility standard.

[cols="1,1,2",options="header"]
|===
|Standard |Target |Applies to

|https://www.w3.org/WAI/standards-guidelines/wcag/[Web Content Accessibility Guidelines (WCAG)] 2.0, 2.1, and 2.2
|Level A and Level AA
|The editor user interface
|===

A target describes what {productname} is developed against. It is not a statement of full conformance. The Accessibility Conformance Report records the measured result for each individual success criterion, and the criteria that are not fully met are listed in xref:known-limitations[Known limitations].

{productname} follows the https://www.w3.org/TR/wai-aria/[Web Accessibility Initiative - Accessible Rich Internet Applications (WAI-ARIA)] specification for the editor user interface.

[NOTE]
====
These targets describe the accessibility of the {productname} user interface. They are separate from the accessibility of the content authored in the editor, which is the responsibility of the content author. To check authored content against https://www.w3.org/TR/WCAG21/[WCAG 2.1] and https://www.access-board.gov/ict/[Section 508] rules, see the xref:a11ychecker.adoc[Accessibility Checker plugin].
====

[[accessibility-conformance-report-vpat]]
== Accessibility Conformance Report (VPAT)

An Accessibility Conformance Report (ACR) records how a product measures against a set of accessibility standards. {companyname} publishes these reports using the https://www.itic.org/policy/accessibility/vpat[Information Technology Industry Council (ITI) Voluntary Product Accessibility Template (VPAT)].

The current report uses the WCAG edition of the template. It covers WCAG 2.0, 2.1, and 2.2 at Level A and Level AA. It does not cover Section 508 or EN 301 549.

[cols="1,1,2",options="header"]
|===
|Version |Published |Report

|{productname} 8.5
|May 2026
|xref:attachment$vpat/TinyMCE_VPAT2.5_WCAG.pdf[Download the Accessibility Conformance Report for {productname} 8.5] (PDF)
|===

The report was produced by expert evaluation through Axess Lab, together with testing across a range of assistive technologies.

Reports are reviewed twice a year and republished alongside a release. When a newer report supersedes an earlier one, the earlier report is retained so that organizations running an earlier release can reference the report that applies to the version they have deployed. For the security and compliance documentation that {companyname} maintains outside of accessibility, see xref:security.adoc#security-assurance-and-compliance[Security assurance and compliance].

[[known-limitations]]
== Known limitations

The following success criteria are recorded as partially supported in the current Accessibility Conformance Report. Each entry corresponds to a finding in that report.

[cols="1,2,1",options="header"]
|===
|Success criterion |Limitation |Affected area

|1.3.1 Info and Relationships (Level A)
|Some relationships within tables are conveyed less clearly than they could be.
|Tables

|3.2.2 On Input (Level A)
|Selecting a character inserts it immediately and closes the dialog, without advance notice that this will happen.
|xref:charmap.adoc[Character Map plugin]

|3.3.2 Labels or Instructions (Level A)
|Buttons that insert invisible or control characters are labeled with those characters, which leaves the buttons without a visible label.
|xref:charmap.adoc[Character Map plugin]

|4.1.2 Name, Role, Value (Level A)
|The character buttons in the dialog are not marked up as buttons.
|xref:charmap.adoc[Character Map plugin]

|1.4.11 Non-text Contrast (Level AA)
|The contrast of the outlines drawn around block-level elements is insufficient.
|xref:visualblocks.adoc[Visual Blocks plugin]

|4.1.3 Status Messages (Level AA)
|Changes to the search results are not communicated to assistive technologies.
|xref:charmap.adoc[Character Map plugin]
|===

[[reporting-an-accessibility-issue]]
== Reporting an accessibility issue

To report an accessibility issue in {productname}, or to request an accommodation, contact link:{supporturl}/[{supportname}].

Include the following information where it is available:

* The version of {productname} in use.
* The browser, operating system, and assistive technology, including version numbers.
* The steps required to reproduce the issue.
* The expected behavior and the observed behavior.

|===
|Screen reader |Vendor

|JAWS
|https://vispero.com/jaws-screen-reader-software/[Vispero]

For the best experience, use https://www.nvaccess.org/[NVDA] together with https://www.mozilla.org/en-US/firefox/products/[Firefox]. Other browser and screen reader combinations are not as well supported, although the editor can be used with a wide variety of combinations.
